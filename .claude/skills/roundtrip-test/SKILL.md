# Roundtrip-тест

Формат: $ARGUMENTS

## Правила

- Тест на встроенном `unittest`, файл `tests/test_roundtrip_<формат>.py`.
- Совместимость с Python 3.7.
- Образцы файлов в репозиторий НЕ кладём (`*.stp` в `.gitignore`). Модель строится кодом, файл пишется во временную папку (`tempfile.TemporaryDirectory()`), после теста удаляется.
- Каждую функцию OCC, которую используешь в тесте, сначала найди в `Win64/python3.7/Lib/site-packages/OCC/Core/<Модуль>.py` (у нас pythonocc 7.4.0; примеры из интернета могут быть для другой версии). Перечисли человеку, где нашёл каждую.
- Чтение и запись — только через реестр/конвертер `cad_io`, а не напрямую через OCC: проверяем именно наш код.

## Шаги

1. **Модель.** 3D — коробка с известными размерами (например 10×20×30) через `BRepPrimAPI_MakeBox`. 2D (DXF) — набор отрезков и окружность с известными координатами.
2. **Записать** во временный файл через writer формата из реестра.
3. **Проверить файл**: существует, размер > 0.
4. **Прочитать обратно** через reader формата.
5. **Сравнить с допуском** (`assertAlmostEqual` с `delta`):
   - точные форматы (STEP, IGES, BREP): объём и габариты (bounding box);
   - STL и другие сетки: только габариты, объём может отличаться или не считаться — допуск больше, в комментарии объясни почему;
   - DXF: число и тип объектов, координаты концов и радиусы.
6. **Негативный случай**: чтение несуществующего или пустого файла даёт понятную ошибку, а не падение интерпретатора.
7. **Запустить**:

   ```
   .\Win64\python3.7\python.exe -B -m unittest discover -s tests -v
   ```

   Показать вывод как есть. Тест красный — не подгонять допуски, а разобраться и сказать человеку.
8. Предложить строку для `TEST_PLAN.md` (`формат | что проверяем | как | статус`) — дописать только после «ок».
