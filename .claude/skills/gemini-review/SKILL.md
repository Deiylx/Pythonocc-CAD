# Ревью Gemini (второе мнение)

Аргументы: $ARGUMENTS (номер раунда: 1 по умолчанию, 2 — последний; можно `--base <ветка>`).

## Правила

- Скрипт запускается **системным** Python: `py tools/gemini_review.py ...` (не `Win64\python3.7`).
  Если `No module named google` — `py -m pip install -r tools/requirements.txt`.
- Ключ берётся только из переменной `GEMINI_API_KEY`. Не читай `.env`, не печатай и не проверяй значение
  ключа — достаточно кода выхода скрипта (2 и «Не задана переменная GEMINI_API_KEY» = ключа нет).
- Реальный вызов отправляет код во внешний сервис. Делай его только по явной просьбе человека
  (вызов `/gemini-review` или «отправь в Gemini» — и есть такая просьба). Ночью / без человека — только `--dry-run`.
- В ревью попадают **только закоммиченные** изменения (`git diff <base>...HEAD`); незакоммиченные видны
  лишь списком в `git status --short`. Если важные правки не закоммичены — скажи об этом до запуска.
- **Не больше двух раундов.** Скрипт отклоняет только `--round 3`; повторный запуск `--round 1/2`
  он не отслеживает — предел держится на тебе: считай раунды в разговоре и не перезапускай раунд «ещё раз».
- Замечания Gemini — мнение, а не факты. Ничего не исправляй без «ок» человека.

## Шаги

1. `git status --short` и `git log --oneline master..HEAD` — показать, что попадёт в ревью.
2. `py tools/gemini_review.py --dry-run --out <scratchpad>/gemini_prompt.txt` (+ `--base`, если задан) —
   показать модель и длину промпта. Если diff обрезан (предупреждение в выводе) — сказать человеку.
3. Раунд 1: `py tools/gemini_review.py --out <scratchpad>/gemini_review_1.txt`.
   Раунд 2 (после исправлений): `py tools/gemini_review.py --round 2 --previous <scratchpad>/gemini_review_1.txt --out <scratchpad>/gemini_review_2.txt`.
   Файлы ответов кладём в scratchpad, не в репозиторий.
4. Показать ответ Gemini **как есть** (не пересказывать, не фильтровать).
5. По каждому замечанию — своя короткая оценка: «согласен / не согласен / проверить», и как проверил.
   Если Gemini называет функцию OCC — найди её grep'ом в `Win64/python3.7/Lib/site-packages/OCC/Core/`
   и напиши результат (найдено в файле … / НЕ НАЙДЕНО).
6. Предложить список правок и **ждать «ок»**. Только после «ок» — правки, тесты встроенным Python
   (`.\Win64\python3.7\python.exe -B -m unittest discover -s tests -v`), затем (если нужно) раунд 2.
7. Каждый реальный вызов уже записан скриптом в `logs/gemini_calls.jsonl` (без ключа). Для журнала
   `logs/AI_LOG_*.md` предложи черновик строки через скилл `ai-log-entry`.
