# Итерация

Цель: $ARGUMENTS

Если цель не указана — спроси её одной фразой и остановись.

## Шаги

1. **Перечитай правила.** Открой `AGENTS.md`. Особенно: куда можно писать, Python 3.7, pythonocc 7.4, `Assemble.py` (GBK) не трогать.
2. **План словами.** Одна цель; шаги, какие файлы изменятся, и список «Не входит» — всё, что нужно, но не относится
   к цели. Если в задаче несколько целей — предложи разбить на итерации (по PR на каждую).
3. **«Ок» нужен не всегда.** Остановись, покажи план и жди «ок» только если:
   - задача меняет что-то в `Win64/` — остановка **перед правками в `Win64/`** (план и точный diff); часть в `cad_io/`
     и `tests/` можно сделать до неё;
   - задача неоднозначна (непонятна цель, противоречит правилам или коду);
   - план приходится менять по ходу (другие файлы или API, выход за цель).
   Иначе задание и есть согласованный план — переходи к шагу 4, а план покажи в итоге.
4. **Один шаг.** Пиши код в `cad_io/` и `tests/` (можно поручить субагенту `coder`). `Win64/` — только после «ок»
   из шага 3, сам (не через `coder`), инструментом Edit, не командами терминала; `Win64/python3.7/`, `Sources/`,
   `Win64/module/Assemble.py` — никогда. Каждую функцию OCC сначала найди в `Win64/python3.7/Lib/site-packages/OCC/Core/<Модуль>.py`. Не нашёл — не используй и скажи об этом.
5. **Тесты** — встроенным Python, из корня проекта (скрипт сам добавляет в PATH каталог DLL OCC):

   ```
   .\tools\run_tests.ps1
   ```

   Покажи последние строки вывода как есть (`OK` или `FAILED` с причиной). Не пересказывай «всё прошло», если не видел `OK`.
6. **Ревью.** Обычный `git diff` не показывает новые (неотслеживаемые) файлы, поэтому:

   ```
   git status --short
   git add -N cad_io tests
   git diff
   ```

   `git add -N` только помечает новые файлы «будут добавлены», ничего не коммитит; после ревью можно вернуть как было: `git reset -- cad_io tests`.
   Передай субагенту `reviewer` **оба** вывода: `git status --short` (видны все изменённые и новые файлы, в том числе вне `cad_io/` и `tests/` — их diff не покажет) и `git diff`. Покажи его замечания и что из них исправлено.
7. **Стоп до коммита.** Коммит, пуш и PR делает человек; ИИ — только по явной просьбе. Основная ветка — `master`.
8. **Журнал** `logs/AI_LOG_<имя>.md` — скилл `ai-log-entry`: формат
   `дата | итерация | PR | кто и чем | цель | ключевой промпт | где ИИ ошибся | как исправили | результат`.
   Колонки «где ИИ ошибся» и «как исправили» заполняет **только человек** — их не заполняй и не предлагай.

## Итог для человека

Коротко: что сделано, что не входит, результат тестов, замечания ревью, черновик описания PR, что предлагается следующим шагом.
