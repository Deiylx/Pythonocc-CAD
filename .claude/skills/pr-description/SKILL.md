# Текст PR

Базовая ветка: $ARGUMENTS (если пусто — `master`).

## Правила

- PR открывает человек (`AGENTS.md`). Твоя задача — текст. Публикация (`gh pr create`) и `git push` —
  только после явного «ок, публикуй» в этом разговоре; «ок» на текст ≠ «ок» на публикацию.
- Всё в тексте — из фактов: команды и их вывод. Не выдумывай результаты тестов, номера итераций и ревью.
- Секретов в тексте нет (ключи, содержимое `.env`).
- Язык — русский, простыми словами.

## Шаги

1. Собери факты (только чтение):

   ```
   git status --short
   git log --oneline <base>..HEAD
   git diff --stat <base>...HEAD
   ```

   Если есть незакоммиченные изменения — скажи об этом первым пунктом: в PR они не попадут.
2. Тесты — запусти заново, встроенным Python, из корня:

   ```
   .\Win64\python3.7\python.exe -B -m unittest discover -s tests -v
   ```

   В PR — последние строки вывода как есть (`Ran N tests` и `OK`/`FAILED`). Упало — так и пиши.
   Если менялись `tools/` или `tests/` — ещё `py -m ruff check cad_io tests tools`, вывод как есть.
3. Журнал: найди в `logs/AI_LOG_*.md` строки этой итерации (номер, «где ИИ ошибся»). Нет строки —
   так и напиши в PR («строка журнала не добавлена») и предложи скилл `ai-log-entry`.
4. Ревью: был ли субагент reviewer и/или Gemini (`logs/gemini_calls.jsonl`, скилл `gemini-review`).
   Галочки в чек-листе ставь только за то, что реально проверено; непроверенное оставь `[ ]` с пояснением.
5. Заполни `.github/pull_request_template.md` целиком (все разделы и чек-лист). Размер: если diff
   больше ~150 строк — напиши это в чек-листе честно, не ставь галочку.
6. Последней строкой тела — `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
   Покажи человеку: заголовок PR (≤ 70 символов) и тело в блоке кода. **Жди «ок».**
7. Только после явного «ок, публикуй»:
   - сохрани тело во временный файл в scratchpad (не в репозиторий);
   - `git remote -v` — проверь, куда смотрит `origin`. PR из форка по умолчанию уходит в чужой
     (исходный) репозиторий — так уже было (см. `logs/AI_LOG_sergey.md`), поэтому `--repo` указывай явно;
   - `gh pr create --repo <owner>/<repo из origin> --base <base> --head <ветка> --title "..." --body-file <файл>`;
   - покажи ссылку на PR из вывода `gh`.
