# AGENTS.md — общие правила проекта для всех ИИ

Этот файл читают все ИИ-помощники (Claude Code, Cursor, Gemini) и мы сами.
`CLAUDE.md` и `GEMINI.md` только ссылаются на него.

## Проект

- BrepCAD (репозиторий Pythonocc-CAD): CAD на Python 3.7, pythonocc-core **7.4.0** (обёртка OpenCASCADE) и PyQt5. Windows. Интерфейс на китайском.
- Задача: добавить импорт/экспорт форматов STEP, DXF (2D) и других (IGES, STL, BREP).
  OBJ — только если найдётся чтение в `OCC/Core`: в нашей 7.4 в `RWObj.py` нет класса-читателя (есть только `RWObj_IShapeReceiver`, `RWObj_Material`, `RWObj_SubMesh`).
- Оценивают процесс работы с ИИ: журналы `logs/AI_LOG_*.md`, ревью, тесты.
- Основная ветка — `master`.
- Общение с человеком, отчёты и записи журналов — по-русски.

## Два Python

- Встроенный Python 3.7 со всеми библиотеками: `Win64\python3.7\python.exe`. Код проекта и тесты запускаются **только им**.
- Системный Python (команда `py`) **3.10 или новее** — для `tools/` (`ai_call.py`, `gemini_review.py`, ruff, хуки):
  google-genai требует Python >= 3.10. OCC в нём нет.
- Ошибка `No module named OCC` = запустили не тем Python.

## Запуск тестов

Из корня проекта, в PowerShell:

```
.\tools\run_tests.ps1
```

Скрипт запускает `.\Win64\python3.7\python.exe -B -m unittest discover -s tests -v` и на время запуска добавляет
`Win64\python3.7\Library\bin` в начало PATH: без него OCC не грузится (`ImportError: DLL load failed`).
Если политика запрещает скрипты: `powershell -ExecutionPolicy Bypass -File tools\run_tests.ps1`
(или `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` — выполнить один раз; настройка сохраняется постоянно для вашей учётной записи).
Флаг `-B` — не создавать файлы `.pyc`. Тесты пишем на встроенном `unittest` (pytest нет).

## Куда можно писать

| Путь | Правило |
|---|---|
| `cad_io/`, `tests/` | Наш код. Можно. |
| `tools/`, `.claude/`, `.github/` | Инструменты. Можно, аккуратно. |
| `Win64/python3.7/`, `Sources/` | **Никогда** не менять. |
| `Win64/module/Assemble.py` | **Не менять и не пересохранять**: кодировка GBK. |
| `Win64/module/`, `Win64/Ribbon/RibbonMain.ini` | Только по согласованию с человеком. Опечатка в `.ini` роняет запуск (там `eval`). |
| `Win64/sketcher/` | Только читать (берём данные для DXF). |
| `Win64/Ribbon/MainWindow.py` | Мёртвый код, не использовать как образец. |
| `.env.example`, `logs/gemini_calls.jsonl` | `.env.example` можно править (только без ключей и секретов). `logs/gemini_calls.jsonl` — машинный журнал вызовов Gemini: его дописывает `tools/ai_call.py` (без ключа и без текстов запросов), коммитим как доказательство работы с ИИ. |
| `.gitattributes` | Можно, аккуратно. Сейчас там `logs/gemini_calls.jsonl merge=union`: при мердже веток строки журнала из обеих сторон сохраняются без конфликта. После мерджа ветки, менявшей `logs/gemini_calls.jsonl`, проверить целостность: каждая строка — целый JSON, строки обеих сторон на месте; порядок строк не важен (время — в поле `time`). Драйвер `merge=union` на кнопке слияния GitHub может не сработать — тогда в своей ветке: `git fetch origin`, `git merge origin/master`, затем push ветки; PR сливается кнопкой. |
| остальные `logs/`, `BUGS.md`, `TEST_PLAN.md`, `PERF.md` | Ведут люди. ИИ пишет только черновики с пометкой «черновик ИИ» и только после «ок»; в журналах `logs/AI_LOG_*.md` ИИ может заполнять все колонки, включая «где ИИ ошибся» и «как исправили», — только по проверяемым фактам (описания и коммиты PR, вывод тестов и ревью), каждая ячейка начинается с «черновик ИИ:». Хуком не проверяется — это дисциплина людей. |

Что реально защищено автоматически: правила `deny` в `.claude/settings.json` и хук `tools/hooks/guard_paths.py`
запрещают встроенным инструментам правки Claude менять `Win64/python3.7/`, `Sources/` и `Assemble.py`.
**Запись через терминал (PowerShell/Bash, скрипты Python) они не блокируют.** Обязательная страховка —
`git status --short` перед ревью: всё, что изменилось вне разрешённых путей, должно быть объяснено или откатано.

## Код

- Совместимость с Python 3.7: без `:=`, без `list[str]`/`dict[str, int]` в аннотациях, без `match`.
- Наши файлы сохраняем в **UTF-8**. GBK только у `Win64/module/Assemble.py`, его не трогаем.
- Наш пакет называется `cad_io` (имя `io` занято стандартным модулем).
- Конвертеры (`cad_io/converters/`) — без окон и кнопок. Окна Qt — только в `cad_io/ui_bridge.py`.
- Все новые надписи для пользователя — в `cad_io/strings.py`, на русском.
- Формат описывается `FormatSpec` из `cad_io/registry.py` (расширение → функция чтения/записи), а регистрируется
  в `cad_io/formats.py` (`register_builtin`; модуль появится в задаче I2): сам `registry.py` не импортирует OCC и Qt.

## Галлюцинации OCC

- Примеры из интернета часто написаны для других версий pythonocc; у нас 7.4.0. Не верь имени функции, пока не нашёл его у нас.
- Перед использованием любой функции OCC проверь, что она есть в
  `Win64/python3.7/Lib/site-packages/OCC/Core/<Модуль>.py`. Не нашёл — не используй и скажи об этом.
- Пример проверки: в нашем `BRepTools.py` есть оба варианта записи BREP — статический метод `breptools.Write`
  (внутри класса `breptools`) и функция модуля `breptools_Write` (строка 253).

## Тестовые файлы

- `*.stp` в `.gitignore`: образцы не попадут в git. Тесты строят модели сами, кодом, и пишут во временную папку (`tempfile`).

## Секреты

- Ключи (`GEMINI_API_KEY` и любые другие) **никогда** не попадают в код, журналы, вывод и коммиты.
  Они лежат только в `.env` (он в `.gitignore`); пример без ключей — `.env.example`.

## Ветки и PR

- Работаем в отдельных ветках. В `master` не пушим.
- PR открывает человек. ИИ коммитит и пушит только по явной просьбе.

## Работа итерациями

1. **Одна цель на итерацию и на PR; что не входит, указываем явно** (в задании, в плане и в описании PR).
   Нужное, но не входящее в цель — в список «Не входит», баги старого кода — в `BUGS.md`.
2. План словами (шаги, файлы). Остановиться, показать план человеку и ждать «ок» нужно только если:
   - задача меняет что-то в `Win64/` — остановка **перед правками в `Win64/`** (план и точный diff, потом явное «ок»);
     работу в `cad_io/` и `tests/` до этого места можно делать;
   - задача неоднозначна (непонятна цель, противоречит правилам или коду);
   - план приходится менять по ходу (другие файлы или API, выход за цель).
   В остальных случаях задание (промпт итерации) и есть согласованный план — работаем без отдельного «ок».
3. Шаг → тесты (`.\tools\run_tests.ps1`) → показать реальный вывод.
4. `git status --short` → ревью: субагент reviewer (Claude Code) или ручная проверка по чек-листу задания (Cursor и др.);
   второе мнение другой ИИ — по желанию.
5. **Стоп до коммита**: коммит, push и PR делает человек (ИИ — только по явной просьбе).
6. Журнал `logs/AI_LOG_<имя>.md` ведёт человек. ИИ может заполнять все колонки строки, включая «где ИИ ошибся»
   и «как исправили», но только по проверяемым фактам: описания и коммиты PR, вывод тестов и ревью. Выдумывать ошибки
   нельзя; нет фактов — «—». Каждая ячейка, написанная ИИ, начинается с «черновик ИИ:»; человек читает и убирает
   пометку, когда согласен, или правит текст (заглушка `<заполняет человек>` не считается заполнением ИИ
   и пометки не требует). «Ошибок не было» ИИ не пишет никогда. Ключ строки — номер PR (колонка «PR»); метки задач из плана (I2–I5 и т.п.)
   идут в колонку «итерация» как названия.

## Инструменты и модели в журналах, PR и ревью

- В журналах, описаниях PR, коммитах и ревью указываем **реальный** инструмент и модель: «Claude Code, Opus 5.5»,
  «Cursor Composer, модель неизвестна», «Gemini 3.8 flash через tools/ai_call.py», «ChatGPT (веб-чат), модель …».
  Модель неизвестна — так и пишем: «модель неизвестна».
- Никаких шаблонных фраз вроде «Написано с Gemini (имя модели укажи)»: каждая строка про ИИ описывает то, что было на самом деле.
  Несколько инструментов — перечисляем, кто что делал.
- Ревью в веб-чате без доступа к репозиторию пишется явно: «ревью в веб-чате <инструмент> по вставленному diff, без доступа
  к репозиторию» — такое ревью не видело файлов вне diff и не запускало тесты.

## Второе мнение (Gemini)

- Gemini API с нашей стороны нестабилен (ошибки соединения, 503, «User location is not supported»), pro-модели без оплаты недоступны.
  Это **необязательное** второе мнение на flash-модели (`GEMINI_MODEL=gemini-3.8-flash`); каждая попытка пишется в `logs/gemini_calls.jsonl`.
- Ревью не блокируется отсутствием ответа Gemini: нет ответа — делаем ревью субагентом reviewer (в Claude Code) или
  вручную по чек-листу задания (в Cursor) и отмечаем это в журнале и PR.

## Честность

- Не выдумывай имена функций, файлов, результаты тестов.
- Тест упал — показать вывод как есть. Не уверен — так и скажи.
- Найденные баги старого кода — в `BUGS.md` (через человека), чиним отдельной итерацией.
